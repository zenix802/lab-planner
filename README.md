# 实验日程 · Lab Planner

在 iPhone / iPad / Mac 上用的实验排程与记录工具：实生苗浇水和营养液、愈伤组织扩繁、组培苗扩繁与生根，每类任务各自的间隔、下一次日期、提前准备，都自动算好；**每天早晚由 GitHub 定时任务主动推送提醒**。

- 做完点一下 ◯：自动记录，并从**实际完成日**顺延出下一次（晚浇一天，下次也往后推）
- 继代类任务自动累计**代数**，提前 N 天提醒你配培养基
- 日历 + 未来 30 天规划视图，周末高亮；可设置“不在实验室”的日期（假期、出差），提前预警期间要到期的事
- 数据存在你自己的 **GitHub 私有仓库**，多台设备自动同步；每次改动都是一条提交记录，可回溯
- 离线可用；可导出 Markdown（贴进 Obsidian）、CSV（Excel）、JSON 备份

## 它是怎么工作的

```
公开仓库 lab-planner（本文件夹）          私有仓库 lab-planner-data（你的数据）
  └─ GitHub Pages 托管应用页面               ├─ data/planner.json      批次/任务/记录
       ↑ iPhone/iPad/Mac 装到主屏幕           ├─ push/                  推送密钥、已登记的设备
       │  读写数据（你的 Token，只授权这一个仓库）├─ scripts/               提醒脚本
       └──────────────────────────────────→ └─ .github/workflows/remind.yml
                                                  每天 07:45 / 20:45（北京时间）运行
                                                  → Apple 推送服务 → 你所有设备的通知
```

为什么是两个仓库：免费 GitHub 账户的 Pages 只能从**公开**仓库发布，而实验数据应该**私有**。所以公开仓库只放通用代码（不含任何数据），数据和提醒任务放在私有仓库里。私有仓库里的所有文件都由应用在第一次连接时**自动写入**，不需要你手动创建。

## 部署（一次性，约 10 分钟，建议在电脑上操作）

### 1. 发布应用（公开仓库）

1. 打开 <https://github.com/new>，仓库名填 `lab-planner`，选 **Public**，点 **Create repository**。
2. 在新仓库页面点 **uploading an existing file**，把本文件夹里的**所有文件和文件夹**拖进去（`index.html`、`sw.js`、`css/`、`js/`、`engine/`、`icons/` 等），点 **Commit changes**。
3. 进入仓库 **Settings → Pages**：Source 选 **Deploy from a branch**，Branch 选 **main**、文件夹 **/(root)**，点 **Save**。
4. 等 1–2 分钟，打开 `https://zenix802.github.io/lab-planner/` 能看到应用就成功了。

### 2. 准备数据仓库（私有）

打开 <https://github.com/new>，仓库名填 `lab-planner-data`，选 **Private**，勾选 **Add a README file**，创建。

### 3. 生成访问 Token

打开 <https://github.com/settings/personal-access-tokens/new>（Fine-grained token）：

| 项目 | 选择 |
|---|---|
| Token name | `lab-planner` |
| Expiration | 能选的最长（过期后生成新的、在设置里重新粘贴即可） |
| Repository access | **Only select repositories** → `lab-planner-data` |
| Permissions → Repository permissions | **Contents**：Read and write<br>**Workflows**：Read and write<br>**Actions**：Read and write |

点 **Generate token**，复制 `github_pat_…` 开头的那串字符（只显示一次）。

### 4. 装到设备上

**iPhone / iPad**（需要 iOS / iPadOS 16.4 或更新）

1. 用 **Safari** 打开 `https://zenix802.github.io/lab-planner/`
2. 点「分享」→「添加到主屏幕」
3. **从主屏幕图标打开**（只有这样 iOS 才允许网页应用发通知）
4. 「设置 → GitHub 同步」：粘贴 Token → 连接并初始化
5. 「设置 → 本机通知」→ 允许通知 → 「发送测试通知 → 完整测试」，约 1 分钟后收到 ✅ 测试通知

**Mac**（macOS Sonoma 14 或更新）：用 **Safari** 打开网址 → 菜单栏「文件 → 添加到程序坞」→ 从程序坞打开，同样粘贴 Token、开启通知。
> Mac 上请用 Safari：Chrome 的网页推送依赖 Google 服务，在国内网络下通常收不到。

每台设备各粘贴一次 Token（可以用同一个）、各自开启通知；数据会自动同步，提醒会推到所有开启了通知的设备。

## 日常使用

**今天**：逾期 / 今天 / 提前准备 / 明天 / 之后 7 天。点 ◯ 完成（5 秒内可撤销）；点整行可以补记其他日期、推迟这一次、跳过、编辑任务。

**新建批次时自动生成的任务**（默认值只是起点，建之前和建之后都能改）：

| 类型 | 自动任务 |
|---|---|
| 实生苗 | 浇水、浇营养液（间隔取自「设置 → 物种与默认间隔」） |
| 愈伤扩繁 | 继代，每 30 天，记录代数，提前 2 天提醒配培养基 |
| 组培苗扩繁 | 继代，每 30 天，记录代数，提前 2 天提醒配培养基 |
| 组培苗生根 | 生根观察（第 14 天）、出瓶炼苗（第 28 天）、移栽（第 35 天） |
| 其他 | 自己添加 |

- **已经在做的批次**：把开始日期填真实的日期，再把每个任务的“下次”改成真正的下一次日期即可。
- **排法**：默认“按实际完成顺延”；像“每周一浇营养液”这种固定节奏，在任务里改成“固定节奏”。
- **计划中的实验**：开始日期填未来的日子，会以“计划播种”出现在待办里，到时候打勾确认。
- **组培苗转生根**：在扩繁批次页点「转生根：新建生根批次」，会自动带上物种和来源关系。

**提醒**（「设置 → 每天提醒」可改时间或关闭，改完会自动更新 GitHub 上的定时任务）：

- 早间 07:45：今天要做的 + 逾期的 + 需要提前准备的 + 即将开始的外出期间有哪些到期
- 晚间 20:45：明天要做的 + 今天还没记完成的
- 没有事项的时段不推送；也可以打开“同时建 GitHub Issue”，装了 GitHub App 会多一路提醒

**记录导出**：「设置 → 数据」可导出 Markdown（按日期整理，直接粘贴进 Obsidian）、CSV（Excel/Numbers）、完整 JSON 备份。

## 常见问题

**收不到通知？**
1. iPhone/iPad 必须是 16.4+，并且是**从主屏幕图标**打开的应用里开启的通知；检查「系统设置 → 通知 → 实验日程」和专注模式。
2. 在「设置 → 发送测试通知」里先点“本机测试”，再点“完整测试”。
3. 看 GitHub 上 `lab-planner-data` 仓库的 **Actions** 页，最近的“实验提醒”运行是否成功（失败时点进去能看到原因）。如果 Actions 被禁用，在仓库 Settings → Actions 里启用。
4. 删掉主屏幕图标后重新添加的，需要重新开启一次通知。

**提醒晚了几分钟？** GitHub 定时任务在高峰期会排队，一般晚几分钟，偶尔半小时左右。

**Token 过期 / 换了新 Token？** 应用会提示“Token 无效”，在每台设备的「设置 → GitHub 同步」里断开后重新粘贴即可，数据不会丢。

**会花钱吗？** 不会。私有仓库每月有 2000 分钟免费 Actions 额度，每天两次提醒大约用 60 分钟/月。

**数据安全吗？** 数据只在你的私有仓库里；Token 只保存在各设备本地，并且只授权了这一个仓库。推送用的密钥也放在这个私有仓库里，只能用来给你登记过的设备发通知。

**国内网络？** `github.io` 偶尔会慢；应用打开过一次后可离线使用，离线时的改动会在联网后自动同步。

## 更新应用

替换公开仓库里改动过的文件，并把 `sw.js` 第一行附近的 `VERSION` 改成新的版本号（如 `1.0.1`）。下次打开应用会提示“有新版本 · 更新”。提醒脚本如有变化，应用会自动同步到数据仓库。

## 文件说明

| 路径 | 作用 |
|---|---|
| `index.html`、`css/`、`icons/`、`manifest.webmanifest` | 页面、样式、图标、主屏幕应用配置 |
| `js/core.js` | 排程核心（下次日期、代数、合并、提醒内容）——应用和提醒脚本共用 |
| `js/app.js` `views.js` `forms.js` `ui.js` `html.js` | 界面 |
| `js/store.js` `github.js` `push.js` | 本地存储、GitHub 同步、推送订阅 |
| `sw.js` | 离线缓存、接收推送、显示通知 |
| `engine/remind.mjs`、`engine/remind.yml` | 提醒脚本和定时任务模板（连接时自动写入数据仓库） |

不依赖任何第三方库或 CDN，所有代码都在这里。
